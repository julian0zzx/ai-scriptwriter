# 001 · 短剧编剧台 — 产品规格（spec）

- 状态：v0.1 已实现（验收中）
- 版本：v0.4 · 2026-10-28
- 关联：`plan.md`（怎么做）、`data-model.md`（存什么）、`contracts/tools.md`（工具接口）、`research.md`（课程依据）
- 产品代号：短剧编剧台 / Duanju Studio
- 插件包：`@ai-scriptwriter/scriptwriter`（host）+ `@ai-scriptwriter/scriptwriter-bundle`（profile bundle）

## 0. 摘要

短剧编剧台是一个 DeepSeek Harness 插件：它把红果《短剧编剧第一课》10 期访谈里的
创作方法，变成一组**模型可直接调用的工具 + 可人工编辑的项目文件 + 可复核的检查报告**。

它不生成视频，不连接平台，不替作者拍板。它做三件事：

1. **把方法变成结构**：立项卡、一句话、人物、三阶段、分集大纲、逐集剧本，各有固定字段，
   字段来自课程，不来自想象。
2. **把结构变成可检查的对象**：格式、时长、钩子、信息差、情绪点、成本、合规、连续性，
   能算的用确定性规则算，算不了的交给带 rubric 的模型评审。
3. **把检查变成可交付的稿子**：按课程的真实剧本格式输出，附机检/评审报告，最后组装投稿包。

一句话：**让模型像短剧编剧一样工作，而不是像聊天机器人一样聊剧本。**

## 1. 问题与判断

### 1.1 要解决的问题

- 通用模型写短剧，常见病是：一集写成长剧、开场铺陈、钩子硬挂、台词像小说、
  场景不可拍、人物写着写着丢了。这些恰好是课程反复讲、且**可以被结构化拦截**的问题。
- 市面上的「AI 写作」多数只给一段文本，没有项目状态、没有分集结构、没有可复核的检查，
  改一集就丢上下文，投出去也不知道哪里不合规范。
- 课程本身是访谈体，信息密度高但不成体系；作者要反复回看、自己整理成清单。

### 1.2 产品判断

- **短剧是产品，不是文学作品**（01）。所以工具的第一性不是「文采」，是**结构、节奏、情绪、
  可拍性**。
- **齐不齐可以算，好不好只能判**。课程里「每集结尾要有钩子」可检查；「这个钩子有没有张力」
  只能评审。两者混成一个分数，就是在骗作者。
- **作者主权不可让渡**。模型可以写十稿，但「这个立项行不行」「前三集能不能过」只能作者说。
- **课程没写的，不发明**。课程对「80–100 集」与「31–80 集」的表述并不完全对齐，
  对「前 3 集」也没有硬标准；这些必须成为可配置默认值，并在文档里如实标注。

## 2. 目标与非目标

### 2.1 目标（v0.1）

1. 在一个空目录里，用工具完成：立项 → 一句话/卖点 → 人物 → 三阶段 → 分集大纲 →
   前 3 集剧本，并得到一份说得清问题的机检报告。
2. 支持逐集写作到全剧体量（默认 80 集），每集都有结构字段、钩子、情绪点与时长核算。
3. 机检覆盖课程中可判定的硬规则；评审覆盖课程中只能判断的软标准；两者分开记录。
4. 作者确认有记录、有门禁；未确认的越级写作会被拒绝，并给出解锁步骤。
5. 导出一份可直接给人看的投稿包（Markdown），格式与课程示例一致。
6. 作为一个可安装的 DSH 插件：装进 web profile 后，新会话出现 11 个 `scriptwriter_*` 工具，
   运行上下文能看到当前项目状态与下一步。
7. 同时产出**可移植的 Skill 包**：`SKILL.md` + 技法 references + 安装脚本 +
   同一份插件 tarball；没有插件时也能作为写作方法手册被 agent 加载。

### 2.2 非目标（v0.1 明确不做）

- 不做视频、分镜、拍摄脚本、配音、字幕文件。
- 不接平台投稿 API，不抓榜单，不伪造播放量/评分/中位值。
- 不做「保证爆款」「保证过稿」「AI 合规认证」。
- 不做多人协作、云同步、版本管理 UI。
- 不做英文创作；输出简体中文。
- 不做 Web 侧边栏面板（列入 v0.2 候选，见 §11）。
- 不自动改写作者已定稿的剧本；评审只给意见，不改正文。

## 3. 用户与场景

| 用户 | 现状 | 用这个插件做什么 |
|---|---|---|
| 新人编剧 | 有热情，缺方法，格式不规范 | 按流程从立项走到前三集，机检兜住格式与结构 |
| 网文作者转型 | 会写情绪，不会写镜头/即时冲突 | 用分集大纲强制即时冲突，用剧本格式强制镜头化 |
| 小工作室编剧 | 一次开多个本子，要快速判断「值不值得写」 | 立项卡 + 评审 + 成本核算，先淘汰再投入 |
| 短剧爱好者 | 想写但不知道从哪开始 | 用模板与检查清单一步步推进 |

典型场景：

- **从零开一本**：用户说「我想写一个重生复仇的短剧，女主被全家害死」→ 工具立项、出三个
  一句话方案、建人物、排三阶段、写前 3 集、机检、评审、等作者确认。
- **只写一集**：已有项目，用户说「第 12 集，女主在宴会上当众揭穿假千金」→ 读项目上下文，
  写大纲条目与剧本，检查钩子/时长/人物连续性。
- **体检一个已有本子**：把已有剧本粘进 `剧集/`，跑全剧机检，按 finding 逐条修。
- **拆解对标剧**：把一部爆款的剧情/台词贴进来，按拉片三层次拆成结构化笔记，供选题参考。

## 4. 用户故事与验收场景

### US-1（P1）从空目录到前三集成稿

作为新人编剧，我想在一个空目录里按课程流程走完立项到前三集，这样我有一份能拿给人看的稿子。

- Given 空工作区，When 调用 `scriptwriter_init` 并填平台/题材/受众/体量，Then 生成
  `.duanju/project.json` 与 `故事大纲.md`，返回下一阶段 blockers。
- Given 立项已确认，When 依次写一句话、人物、三阶段、分集大纲、第 1–3 集剧本，
  Then 每步都有对应的 Markdown 文件，且机检无 error。
- Given 前三集完成，When 跑 `scriptwriter_review kind=opening`，Then 返回逐条问题（引用原文），
  记录 rubric 版本与模型，不修改剧本文件。

### US-2（P1）逐集写作不丢上下文

作为连载编剧，我想写第 N 集时工具知道前面所有设定与伏笔，这样人物不会丢、钩子不会重。

- Given 已有 1–11 集，When 写第 12 集，Then 工具读取人物表、三阶段、前情与未回收伏笔，
  在结果里列出「本集可用的伏笔/必须延续的人物」。
- Given 第 12 集剧本里出现未登记角色，When 跑机检，Then 报 `CON-001` 并指名场景与行号。

### US-3（P1）投稿前体检与导出

作为编剧，我想在投出去之前知道格式、时长、钩子、成本、合规哪里有问题。

- Given 全剧已写，When 跑 `scriptwriter_check scope=all`，Then 生成 `审查报告.md`，
  按 severity 汇总，每条 finding 带 code、ruleRef、文件/集/场/行、修改建议。
- Given 作者已确认交付，When `scriptwriter_export kind=submission`，Then 生成 `投稿包.md`，
  含剧名、一句话、人物小传、分集大纲、前 3 集剧本、检查摘要、待确认事项。

### US-4（P2）拆解对标剧

作为选题阶段的编剧，我想把爆款拆成可复用的结构，而不是只收藏一个链接。

- Given 用户贴入一部剧的剧情/台词，When `scriptwriter_dissect upsert`，Then 在 `竞品拆解.md`
  生成结构化条目：一句话、三阶段任务、1-1 开场、钩子类型与位置、情绪点、可复用点。

### US-5（P1）作者确认与门禁

作为作者，我不希望模型在我没点头之前一路写下去。

- Given 立项未确认，When 写第 1 集，Then 拒绝，并给出「先调用 `scriptwriter_confirm kind=settings`」。
- Given 前三集未确认，When 写第 4 集，Then 拒绝，并给出「先跑 opening 评审并确认」。
- Given 作者只说「可以」，When 调 `scriptwriter_confirm`，Then 必须同时记录作者原话与摘要；
  只有摘要没有原话的确认被拒绝。

### US-6（P2）多项目并行

作为工作室编剧，我在一个 DSH 进程里开多个工作区。

- Given 会话 A 在项目甲、会话 B 在项目乙，When 各自调用工具，Then 只读写各自根目录，
  不出现「A 的项目被写进 B」或「服务只认启动目录」。

### US-7（P2）技法速查

作为写作者，我想在写某一场时马上看到课程对「钩子/开场/台词」的要求。

- Given 任意阶段，When `scriptwriter_status detail=craft topic=hook`，Then 返回钩子技法表
  （两类主干 + 子类 + 案例型 + 反例），每条带课程出处；不写入任何文件。

## 5. 功能需求（FR）

### 5.1 项目与工作区

- **FR-101 立项**：`scriptwriter_init` 必须能创建项目（标题、平台、题材、受众、集数、
  单集秒数、成本档、可选一句话），并生成 `project.json` 与 `故事大纲.md` 骨架。
  已存在项目时默认**不覆盖**，返回现有摘要与「如何修改」；覆盖必须显式 `overwrite=true`。
- **FR-102 工作区隔离**：每个工具调用从 `exec.agent.session.header.cwd` 解析项目根；
  缺省回退到配置的 `workspaceRoot`，再回退到进程目录。不同根目录的缓存互不污染。
- **FR-103 文件优先存储**：内容存 Markdown（YAML frontmatter + `##` 小节 + ```yaml 块），
  元数据存 `.duanju/project.json`。读取时以文件为准；文件语法错误必须报错并指名文件/行，
  不得静默丢弃或用旧值覆盖。写入必须先写内容文件、后写索引；部分失败要逐项报告。
- **FR-104 运行上下文**：向 system prompt 注入一段项目上下文：项目名、当前阶段、
  已完成/计划集数、下一阶段 blockers、最近一次机检 error 数、建议下一步。
  渲染必须同步、非阻塞（快照缓存），且按会话所属工作区取数。
- **FR-105 故事卡**：`scriptwriter_story operation=pitch` 必须能写：一句话（四槽位：
  主角/目标/阻碍/亮点）、核心欲望、核心情绪、差异化（≥1）、对标（可选）、结局。
  缺槽位时返回 blockers，不静默通过。
- **FR-106 三阶段**：`scriptwriter_story operation=stage` 必须能设置阶段区间、阶段任务、
  阶段小目标、信息差模型；区间必须连续覆盖全剧、不重叠。
- **FR-107 人物**：`scriptwriter_cast` 必须能增删改人物：姓名、角色（主角/反派/核心伙伴/
  功能角色）、阵营、欲望、痛点、性格、说话方式、成长弧、成本档、首次出场、退场、
  关系。写剧本时出现未登记人物必须可被机检发现。
- **FR-108 分集大纲**：`scriptwriter_outline` 必须能按集写：标题、所属阶段、本集目标、
  冲突、情绪点类型、大/小情绪点、信息差、钩子类型、钩子文本、前 30 秒三要素、
  中段三要素、末 30 秒、出场人物、场景、备注。支持批量写入 1–N 集。
- **FR-109 剧本格式**：`scriptwriter_script operation=write` 接收完整单集剧本，按课程格式解析：
  `第N集`、`【本集任务/转折/卡点】`、`1-1 日 内 地点`、`人物：`、`△动作`、
  `角色（语气/动作）：台词`、`角色OS：`、`VO`、`【闪回】/【闪出】`、`（字幕：…）`。
  解析失败必须给出 FMT 错误与行号，不得部分静默写入。解析-渲染必须可往返。
- **FR-110 写作门禁**：写第 1 集前必须有 `settings` 确认；写第 4 集及以后必须有
  `opening` 确认；`status=final` 必须有最近一次机检无 error。拒绝时必须返回解锁步骤。
- **FR-111 钩子**：每集必须有钩子类型与钩子文本；`scriptwriter_script` 写入时把
  `hookScene` 记为最后一场场号，机检校验它确实等于最后一场、且【卡点】非空。
  钩子类型必须来自课程枚举（台词钩/画面钩及其子类 + 案例型四类）。
  连续 N 集（默认 3）使用同一类型时给 warn，不阻断。
- **FR-112 节奏与主线检查**：检查三阶段是否覆盖、阶段任务是否填写、大期待是否在
  第 1–2 集出现、核心目标是否唯一且具体、集号是否连续、已写集是否都有大纲条目。
- **FR-113 台词检查**：统计并标记：单句过长（默认 >60 字 warn，>100 字强提醒 warn）、
  OS/VO 占比过高（默认 >30% warn）、连续对白过多（>6 行 warn）、水词/套话命中、
  动作段落过长（>100 字 warn）。**这些数字课程均未给出**，属于插件默认阈值：
  报告里必须标 `CFG-*` 而不是 `DR-*`，且项目可改。台词类阈值一律不升级为 error。
- **FR-114 成本与可拍性检查**：统计单集场次数、独立场景数、出场人数、特殊元素
  （夜景外景、雨、水下、爆破、车辆、动物、儿童、古装、特效等标签），
  按项目成本档给出 warn；跨集合计独立场景与人物。以 80 集为例，核心人物 3–5、
  其余 ≤20、高潮集新角色 ≤2 为课程默认（DR-28），超出按 warn 提示，不阻断。
- **FR-115 合规提醒**：用**版本化**的分类清单扫描（暴力血腥、性暗示、赌博毒品、
  迷信、未成年、虐待、炫富拜金等），全部为 info/warn 级「需人工复核」；
  输出永不包含「合规通过」。清单来源与版本写入报告。
- **FR-116 连续性检查**：未登记人物、已退场人物再次出场、伏笔到期未回收、
  集号重复/缺失、场景号重复、同一人物在同一场重复列名；地点以「本集大纲的
  `locations`」为准，剧本出现大纲外地点记 warn。
- **FR-117 机检报告**：`scriptwriter_check` 返回 findings，每条含 `code`、`severity`、
  `ruleRef`（课程规则用 `DR-*`，插件默认阈值用 `CFG-*`）、`location`（文件/集/场/行）、`message`、`evidence`、
  `suggestion`；同时写 `.duanju/reports/check-*.md` 与最新汇总 `审查报告.md`。
  机检**不得调用模型**。
  严重度口径：`error` 只给「破坏可拍/结构硬规则」——格式解析失败、集末无钩子、
  钩子类型非法、已写集缺本集大纲；其余为 `warn`/`info`。`error` 阻断 `final` 与
  「无 error」判断，但不阻止草稿保存。
- **FR-118 模型评审**：`scriptwriter_review` 支持 `opening|hook|emotion|dialogue|shootability|full`；
  必须用版本化 rubric，返回逐条 `{severity, quote, issue, fix}` 与总判断
  （`pass|revise|fail`），记录 provider/model/rubric 版本；**不得修改任何剧本/大纲文件**。
  无可用模型时明确报错，不伪造结果。
- **FR-119 技法表**：`scriptwriter_status detail=craft` 提供 `format|opening|hook|rhythm|emotion|
  dialogue|pitch|compliance|budget|submission|dissect` 等主题；内容来自课程，带出处；
  按需返回，不一次性塞进上下文。
- **FR-120 作者确认**：`scriptwriter_confirm` 支持 `settings|opening|episode|delivery`；
  必须同时记录 `summary`（批准的版本）与 `userWords`（用户原话）；缺一拒绝。
  确认记录写入 `project.json`，并驱动 FR-110 的门禁。
- **FR-121 状态面板**：`scriptwriter_status` 返回：阶段、下一步、blockers、集数覆盖、
  字数/时长分布、最近机检摘要、未回收伏笔、成本估算、确认状态。
  `detail=episode` 返回单集契约+剧本+检查摘要；`detail=bible` 返回人物/阶段/伏笔。
- **FR-122 导出**：`scriptwriter_export` 支持 `submission|scripts|outline|report|all`；
  生成稳定文件名的 Markdown；投稿包必须含 9 项：剧名/题材/受众/体量、一句话、
  卖点/差异化、人物小传、三阶段、分集大纲、前 3 集剧本、检查摘要、待确认事项。
  `submission` 需 `delivery` 确认。
- **FR-123 竞品拆解**：`scriptwriter_dissect` 必须能增删改查结构化竞品条目：
  剧名、平台/体量、一句话、1-1 开场、三阶段任务、钩子模式、情绪点、可复用点；
  存 `竞品拆解.md`，不抓取网络。
- **FR-124 伏笔台账**：`scriptwriter_story operation=promise` 记录伏笔：埋设集、到期集、
  回收方式、状态；到期未回收由机检报 `STR-007`。
- **FR-125 版本与迁移**：`project.json` 带 `schemaVersion`；升级时把旧结构读成新结构，
  写回时保留未知字段；遇到未来版本必须拒绝写入并提示升级插件。
- **FR-126 可操作错误**：所有拒绝/失败信息必须包含：什么坏了、在哪、怎么修
  （具体到下一次工具调用）。禁止只回「参数错误」。
- **FR-127 双产出物**：一次构建必须产出两个可分发物：①DSH 插件 tarball
  （`ai-scriptwriter-<version>.tgz`，可 `dsh plugin add`）；②Skill 目录与压缩包
  （`SKILL.md`、`references/`、`scripts/install.sh`、同一份插件 tarball）。
  两者来自同一份 `core/craft.ts`，references 由构建生成，不手写第二份。
  Skill 必须能被 DSH 的 `dsh-skill-filesystem` 从 `~/.dsh/skills/ai-scriptwriter/`
  或项目 `.dsh/skills/` 发现；`install.sh` 只做复制与提示，不偷偷改 profile。

## 6. 领域规则（DR，课程可追溯）

> 标注：**[明确]** 课程原文直接给出；**[推论]** 由课程多处表述合并而来；
> **[未明确]** 课程没有给出数字/标准，插件只做可配置默认。
> 每条规则的原文依据与要点见 `research.md`。

### 6.1 体量与形式

- **DR-01 [明确]** 短剧是竖屏、单集约 3 分钟、强情绪与代入感的内容产品；核心不是深刻道理，
  是碎片时间里的幻想体验。（01 §01、§02）
- **DR-02 [明确/不一致]** 单集时长：01 期约 3 分钟；10 期每集 1–2 分钟；08 期 1–3 分钟；
  09 期「可能就一两分钟」；单集通常 500–800 字（03 §六大坑 01）；全剧多为 80–100 集
  （04、05）。课程同时以「第 31–80 集」为收束期，81 集以后未说明。
  → 插件默认 80 集 × 90 秒，字数窗口 500–800；全部可配置，并提示口径差异。
  课时长与字数/秒的换算从未给出，`charsPerSecond` 是插件默认值，不是课程规定。
- **DR-03 [明确]** 三阶段：第 1–10 集黄金窗口（立主线、亮看点）、第 11–30 集稳固发展
  （主线实质推进、可开副线）、第 31–80 集高潮收束（伏笔揭晓、多轮反转）。
  第 10 集是留存/付费情绪闸门。（05 §01–03、导语）
- **DR-04 [明确]** 平台/制作方最先看第一集第一场（1-1）；弃剧集中在第一集；
  前 30 秒要交代背景、困境、动机；前 20 秒要抓人。（03 §第一关/第三关、05 单集结构）
- **DR-05 [明确]** 开场一集内必须讲清「身份 + 困境 + 目标」黄金三角。（03 文末自查）
- **DR-06 [明确]** 开场五要素：清晰人设、明确主线目标、强烈困境代入、持续情绪推进、
  有效信息密度。（03 §工具箱）
- **DR-07 [明确]** 开场结构：起（高能切入）/ 承+转（行动与升级）/ 合（悬而未决）。（03）
- **DR-08 [明确]** 开场六坑：节奏拖沓、台词冗余、人设模糊、受众错位、情绪空洞、缺少创新。（03）
- **DR-09 [明确]** 一句话故事四要素：主角 + 目标 + 阻碍 + 亮点（金手指/独特设定）。（04）
- **DR-10 [明确]** 主角一秒共情靠「良善受欺」：先立良善与付出，再让之被辜负。（04）
- **DR-11 [明确]** 必须明确「为谁而写」：男频偏小人物逆袭，女频偏情感/CP/人设；
  不同年龄对重生/系统/穿书与现实题材接受度不同。（04）
- **DR-12 [明确]** 大纲三件套：故事梗概（只写高光关键事件）、人物小传（背景/性格/
  核心目标/记忆点）、看点亮点（一两句话说清凭什么爆）。阶段大纲约 500 字/前 10 集，
  必含背景、出场人物、阶段核心事件、关键悬念/冲突/高光卡点。（04）
- **DR-13 [明确]** 剧本格式：集数、日/夜、内/外、地点、场次（1-1）、人物、△动作、
  （）语气神态动作、闪回/闪出、OS/VO、卡点标注；剧本是拍摄指南，不是文学作品。（01 §规范）

### 6.2 节奏与单集结构

- **DR-14 [明确]** 单集三段：前 30 秒（背景+困境+动机）、中间 1 分钟（推主线/揭关系/
  埋新伏笔）、最后 30 秒（强悬念/未完成动作/意味深长台词/突转）。（05 单集结构）
- **DR-15 [明确]** 大期待 = 主角终极目标，最晚第 2 集直白给出；全剧只保留一个核心目标，
  且要具体（含数字/期限更好）。（06 §01、避坑 §01）
- **DR-16 [明确]** 小期待 = 把大目标拆成阶段任务，像游戏任务一样逐级完成；
  示例按每 20 集一阶段。（06 §02）
- **DR-17 [明确]** 悬念靠信息差，四种模型：主角知/观众配角不知；配角观众知/主角不知；
  观众知/主角配角不知；主角观众知/配角不知。一部剧可换用多种，阶段之间应有变化；
  信息差须建立在合理认知落差上。（06 §01–02、案例解析）
- **DR-18 [明确]** 钩子 = 把高潮拆成两半，让一集结束在高潮爆发前一秒，制造未完成感；
  每集结尾都要有钩子；主干为台词钩（未说完的质问/身份暗示/目标宣言）与画面钩
  （情感切掉/动作中断/意外身影/熟悉面孔），案例另见突发危机/关键人物登场/
  怀疑未确认/关键物件丢失。（06 §02）
- **DR-19 [明确]** 无效钩子：用内心独白复述目标或解释剧情；钩子必须依托剧情自然停顿，
  不能结尾硬挂。（06 避坑 §03）
- **DR-20 [明确]** 台词必须口语化、简洁、符合身份年龄职业性格、推动剧情；杜绝水词；
  避免五六行以上的长台词和大段旁白。（01 §台词、05 §台词设计）
- **DR-21 [明确]** 台词三大功能：推动剧情、塑造人物、调节奏/埋伏笔/做呼应。（09）
  对白是主力，OS/VO 尽量少用、只承担画面无法表达的内容；能对白表达就不用画外音，
  能用表演呈现就不用独白。（09 §表现形式）
- **DR-22 [明确]** 剧本要有镜头化思维；避免上帝视角；不要把心理描写当 OS 念；
  场景与人物要可落地。（08、09）

### 6.3 情绪与人物

- **DR-23 [明确]** 情绪点四类：逆袭成功、反转打脸、意外收获、CP 甜宠。
  大小搭配：每集 1 个小情绪点，每 5–10 集 1 个大情绪点；允许蓄力集不释放，
  但连续多集无释放要告警。（07 §01–02）
- **DR-24 [明确]** 痛点：男频三类——安全感被打破（背叛/失业/被驱逐）、尊严受损
  （当众被贴「窝囊废」）、无法保护家人；女频两类——情感安全感被打破、自我价值
  不被认可。痛点要贴近生活、具象成场景。（07 §01–03）
- **DR-25 [明确]** 困境尺度三条：展现简洁（铺垫完成即转应对/转机）、留希望
  （细节暗示反击准备或潜在助力）、有针对性（来自动机合理的对立角色或明确矛盾）。
  避免「不劳而获」的悬浮感；不要靠打脸路人（践踏弱者）制造情绪点。（07）
- **DR-26 [明确]** 合规三维：价值观与伦理、政策与法律、表现尺度；
  平台审核趋务实，红线不能碰。（08 §合规）
- **DR-27 [明确]** 写剧本要算「经济账」：每加一个新场景可能多一天拍摄；夜戏/外景更贵；
  水下、高空、飙车、爆破、特效、大群演除非是核心卖点，否则简化。（08 §经济账）
- **DR-28 [明确]** 角色数量（以 80 集为例）：核心人物 3–5 人，其余不超过 20 人；
  高潮集新引入角色 ≤2 个，日常集尽量不引入；每个配角至少承担推动情节/衬托主角/
  提供关键信息之一，并写得出「他为什么必须存在」。（08 §角色设计）
- **DR-29 [明确]** 节奏四要素：情节编排（冲突连锁）、台词设计（字字千斤）、
  人物关系（关系变化即节奏）、情感控制（情绪引导节奏）。（05 §01–04）
- **DR-30 [明确]** 拉片三层次：一句话概括全剧、按阶段拆任务、精研单集框架
  （开场 3 秒设钩、冲突建立、反转、结尾卡点）；拉片四问：怎么切入/30 秒怎么建情绪/
  冲突怎么升级/钩子怎么卡。（01 §拉片、05 §拉片）
- **DR-31 [明确]** 初稿后做减法：删不推主线的桥段、多余人物、累赘设定与台词；
  避免同类桥段重复，变化要是「类型转换」。（05 §做减法、避坑）
- **DR-32 [明确]** 选题三类：常青型拼完成度、脑洞型拼差异化、热门题材拼「新酒装旧瓶」；
  微创新三法：人设、背景、叙事视角与情绪逻辑；选题五问（用户/情绪/可视化/红线/数据）。（02）
- **DR-33 [明确]** 起名要抓卖点，让审核一眼知道讲什么、有什么看点；改编尽量保留
  原著核心关键词。（02）
- **DR-34 [明确]** 网文转短剧：从自由段落转标准格式、从作者视角转观众视角、
  从长线铺垫转即时冲突；提纲先行。（10）
- **DR-35 [明确]** 先写得清楚，再追求惊艳；格式混乱的剧本可能在初审就被淘汰。（01 §规范）
- **DR-36 [明确]** 情绪点三误区：情绪自嗨（没站在观众视角）、逻辑缺失（为爽而爽、
  反派降智）、打脸路人（对象应是主要反派，不能靠践踏弱者）。（07 避坑）
- **DR-37 [明确]** 交稿前自查顺序：先故事内核（一句话说清、是否独特），再落地性
  （场景/预算/审核风险），最后完整度（主线、节奏、人物统一、逻辑硬伤、台词可表演）。（08）
- **DR-38 [明确]** 台词修改法：每句自问「以他的性格/身份/情境会不会这么说」；
  分角色朗读；把一段台词砍掉三分之一，核心信息还在就砍。（09 §打磨）
- **DR-39 [明确]** 台词要能转化为演员的动作或表情；少写心理、多写行为；
  关键信息必须由正文传递，不能假设观众看过人物小传。（08 §镜头化/上帝视角、09）

## 7. 非功能需求（NFR）

- **NFR-01 离线**：插件不发起网络请求；无平台数据也完整可用。
- **NFR-02 确定性**：机检对同一输入产生同一输出（排序稳定、无时间依赖的判定）；
  报告可重复生成，时间戳除外。
- **NFR-03 性能**：单集机检 < 200ms（80 集全量 < 5s，普通笔记本）；
  项目读取不阻塞模型步骤（上下文用快照）。
- **NFR-04 安全**：所有文件操作受 `ctx.fs` 沙箱约束，不越出会话工作区；
  不写 `~/.dsh`；安装动作只在用户批准后执行。
- **NFR-05 兼容**：锁定 DSH `0.2.1-rc.2`；不使用私有 API；升级需先改 `plan.md`。
- **NFR-06 数据安全**：多文件写入部分失败必须报告；解析失败不覆盖；迁移不丢字段。
- **NFR-07 可测试**：`core/` 纯函数可单测；工具层可用内存 FS 做集成测试；
  至少一个 golden 项目 fixture 覆盖「立项→前三集→机检→导出」。
- **NFR-08 可维护**：单个工具实现不跨文件堆叠；finding 码、DR 码稳定；
  新增规则必须同时加 spec 条目、测试、报告文档。
- **NFR-09 文案**：工具描述与错误信息为简体中文，面向写作者，不用内部术语吓人。

## 8. 成功标准（SC）

- **SC-01 全链路**：空工作区 → 80 集分集大纲 + 前 3 集剧本，全流程只用插件工具完成，
  最终机检 0 error；在一个会话内可复现。
- **SC-02 格式**：生成的剧本 100% 可被解析器重新解析（往返稳定），每条 action/dialogue
  都能定位到集/场/行；格式错误有 FMT 码与行号。
- **SC-03 钩子**：已写集 100% 有 `hookType` 与 `hook`，且最后一场被标记为钩子场；
  钩子类型全部落在课程枚举内。
- **SC-04 长度**：已写集字数落在项目窗口（默认 500–800）内，估计时长在目标 ±20%；
  越界给出可执行的删/补建议。
- **SC-05 机检**：`scriptwriter_check` 不触发任何模型调用；单集 < 200ms；每条 finding
  带 `ruleRef`；报告落盘且可重复。
- **SC-06 评审**：评审记录含 provider/model/rubric 版本与逐条引用；评审不改变任何
  剧本字节；无模型时返回明确错误。
- **SC-07 门禁**：未确认 settings 写第 1 集被拒；未确认 opening 写第 4 集被拒；
  未确认 delivery 导出投稿包被拒；拒绝信息包含解锁步骤。
- **SC-08 导出**：投稿包含 §5 FR-122 的 9 项；重复导出内容稳定（时间戳除外）。
- **SC-09 安装**：tarball 装进 web profile 后，`--dump-config` 可见 `duanju` 行；
  新会话出现 11 个 `scriptwriter_*` 工具；启动无报错。
- **SC-10 质量**：`pnpm run typecheck && pnpm test && pnpm run build` 全绿；
  `core/` 行覆盖率 ≥ 90%；所有 FR 至少一个测试或明确的人工验收记录。
- **SC-11 诚实**：无网络调用；合规输出无「通过」；文档中「未明确」的课程口径
  不被描述成硬标准。
- **SC-12 隔离**：两个不同 cwd 的会话各自读写自己的项目，互不产生文件。
- **SC-13 Skill 产出物**：`dist/skill/ai-scriptwriter/SKILL.md` 的 frontmatter
  （name/description）可被 DSH 技能发现器解析；references 覆盖格式/开场/钩子/节奏/
  情绪/台词/合规/投稿；`install.sh --dry-run` 不写文件；skill 内含与插件同版本的 tarball。

## 9. 关键实体

详见 `data-model.md`。概要：

- `Project`：设置、schema 版本、确认记录、报告索引。
- `Story`：一句话四槽、核心欲望/情绪、差异化、对标、三阶段、结局、伏笔台账。
- `Character`：身份、欲望、痛点、性格、说话方式、弧光、成本档、进出场、关系。
- `EpisodePlan`：阶段、目标、冲突、情绪点、信息差、钩子、三段结构、人物、场景。
- `Script`：集号、状态、场景（场次/日夜/内外/地点/人物/动作/台词）、钩子场、
  字数/估计秒数。
- `Promise`：伏笔、埋设集、到期集、回收方式、状态。
- `Finding`：code、severity、ruleRef、location、evidence、suggestion。
- `Review`：kind、rubric、provider/model、verdict、findings、时间。
- `Confirmation`：kind、summary、userWords、时间。
- `Dissection`：竞品名、体量、一句话、开场、阶段任务、钩子、情绪、复用点。

## 10. 不做什么（再次强调）

- 不把「机检通过」说成「剧本合格」。
- 不把「评审 pass」说成「平台会过稿」。
- 不替作者确认、不编造作者反馈、不伪造数据。
- 不在用户没要求时把文件写进 `~/.dsh` 或项目目录之外。
- 不用「AI 味」的营销文案写工具描述；说人话。

## 11. 假设与待澄清

### 11.1 当前假设（可被用户推翻）

- A1：一个工作区 = 一个短剧项目（v0.1 不做多项目同目录）。
- A2：默认体量 80 集 × 90 秒；用户可在 `scriptwriter_init` 改。
- A3：内容用简体中文；平台字段自由文本（红果/抖音/快手等）。
- A4：评审默认使用会话当前模型；可配置固定 provider/model。
- A5：v0.1 默认只做工具与文件，不做 Web 面板；若 Q1 选做则进入 v0.2。

### 11.2 需要用户决定

- **Q1 交互面**：v0.1 只做工具（推荐）还是同时做 Web 侧边栏面板（项目卡/集数进度/
  问题列表）？面板会让「看得见进度」，但工作量约增加 1/3。
- **Q2 安装**：是否允许把插件装进当前 `~/.dsh/profiles/web`（会写工作区外文件，
  需重启 `dsh web` 才能生效）？还是只交付 tarball + 安装命令？
- **Q3 默认体量**：80 集 × 90 秒（课程常见区间）作默认，还是 60 集 × 120 秒
  （更接近「每集 1–3 分钟」的上限）？或两者都不设，`init` 时必须问？
- **Q4 评审粒度**：评审是「按集」为主（省 token、快），还是「全剧一次」为主
  （能看曲线但贵）？计划默认「开篇/全剧各一次 + 单集按需」。

## 12. 术语

| 术语 | 含义 |
|---|---|
| 1-1 | 第一集第一场；平台筛选时最先看的位置 |
| 大期待 / 小期待 | 全剧终极目标 / 阶段任务 |
| 信息差 | 观众、主角、配角对同一事实的知情差 |
| 钩子 / 卡点 | 集末让观众点下一集的未完成瞬间 |
| 黄金三章（本产品） | 第 1–3 集；课程未用此词，产品用它指「开篇确认」的范围 |
| 机检 | 确定性规则检查，不调用模型 |
| 评审 | 带 rubric 的模型判断，记录模型与版本 |
| 投稿包 | 给人看的交付件：一句话/人物/大纲/前 3 集/检查摘要 |
