### 2.2 课程内部的四组不一致

1. **单集时长**：01 说约 3 分钟；10 说 1–2 分钟；08 说 1–3 分钟；09 说可能只有一两分钟。
   → 不设唯一真值。`secondsPerEpisode` 默认 90，可 60–180；报告只按项目设置核对。
2. **阶段划分**：05 用 1–10 / 11–30 / 31–80；01 的拉片法用前10 / 10–30 / 30–60 / 60–结局。
   → 项目阶段默认 3 段（05）；拉片模板保留 4 段（01）。两者不混用。
3. **「前 3 集」**：03 的实际颗粒度是 1-1 与第 1 集；08 说「前三集立主线」。
   → 产品把第 1–3 集定义为一个作者确认关口（opening），并明说这是产品设计，
   不是课程原话。
4. **字数与秒数的换算**：课程没有给出「每秒多少字」。500–800 字/集与 1–3 分钟/集
   无法同时精确成立。→ `charsPerSecond` 是插件默认（5.5），并在报告里同时给
   字数和估计秒数，不把估计值伪装成事实。

### 2.3 课程未明确的项（不得写成 DR）

- 单集场数上限、单集场景数上限、台词单句字数上限、OS/VO 占比上限；
- 成本档位（低/中/高）的具体金额与场景折算；
- 每集必须有几个反转、几个笑点、几个爽点；
- 平台投稿的具体文件格式、命名规范、字数格式；
- OS 与 VO 的定义差别（样例中 OS 用于心声、VO 用于开口，正文未解释）；
- 「前 3 集」的硬标准、81 集以后的阶段安排；
- 评分/打分体系（课程从未给分）。

→ 这些全部落到 `CFG-*` 阈值或评审提示，可配置、可关闭，并在报告里标「插件默认」。

### 2.4 处理原则

1. 课程明确 → 规则（DR）+ 机检 finding（error/warn 视后果）。
2. 课程不一致 → 项目设置 + 默认值 + 文档提示；不选边站。
3. 课程未明确 → 插件默认（CFG）或评审建议；**不冒充课程规则**。
4. 任何默认值都要能被 `scriptwriter_init` / `project.json` 改。

## 3. 规则证据（DR 与课程）

### 3.1 体量与形式

- **DR-01**：短剧是「成年人的童话」，竖屏、单集约 3 分钟，核心是强烈情绪点与代入感；
  观众要的是碎片时间里的幻想体验，不是深刻道理。（01 §01–02）
- **DR-02**：单集 1–3 分钟、500–800 字、全剧 80–100 集；三处口径不一致（见 §2.2）。
  （01 §01、03 §六大坑 01、04、05、08、09、10）
- **DR-03**：三阶段任务与第 10 集情绪闸门。黄金窗口期要「立主线、亮看点」；发展期
  「主线实质推进、可开副线」；收束期「伏笔揭晓、多轮反转」。（05 §01–03）
- **DR-04**：平台最先看 1-1；弃剧集中在第一集；前 30 秒交代背景/困境/动机；
  前 20 秒抓人（03 案例）。（03 §第一关/第三关、05 单集结构）
- **DR-05**：一集内讲清「身份+困境+目标」黄金三角，是 03 文末明确的自查标准。（03）

### 3.2 开场

- **DR-06**：开场五要素：清晰人设、明确主线目标、强烈困境代入、持续情绪推进、
  有效信息密度。每条都有反例：身份靠旁白 vs 靠事件；目标空泛 vs 具体；
  困境不惨 vs 有压迫感；情绪平 vs 过山车；台词单职 vs 多职合一。（03 §工具箱）
- **DR-07**：起/承+转/合；合必须悬而未决，三种收法：话到一半、动作定格、
  真相呼之欲出。（03）
- **DR-08**：六大坑：节奏拖沓、台词冗余、人设模糊、受众错位、情绪空洞、缺少创新。
  其中「短剧一集通常 500–800 字」是唯一明确字数。（03 §六大坑）
- 开场三关（过筛/下限/留存）是评审 rubric 的骨架：木桶效应与流量漏斗说明
  「开场不是加分项，是乘数」。（03 §三关）

### 3.3 主线与大纲

- **DR-09**：一句话四要素 = 主角 + 目标 + 阻碍 + 亮点。反例「一个男孩重生复仇的故事」
  缺具体信息；正例含身份、目标、阻碍、先知能力。（04 §三问 01）
- **DR-10**：一秒共情靠「良善受欺」：先立良善与付出，再让之被辜负；不是卖惨。（04 §三问 02）
- **DR-11**：为谁而写：男频偏小人物逆袭，女频偏情感/CP/人设；年龄层决定题材接受度。
  （04 §三问 03）
- **DR-12**：大纲三件套：故事梗概只写高光、人物小传四字段、看点亮点一两句；
  阶段大纲约 500 字，必含背景/人物/阶段事件/关键悬念冲突高光卡点。（04 §三件套）
- 大纲三坑：流水账（按时间罗列）、副线喧宾夺主、幸存者偏差。（04 §三坑）

### 3.4 剧本格式

- **DR-13**：课程给了两层格式：四行式模板（集/日夜/内外/地点/场次/△/()/闪回）
  与凉白开真实样例（紧凑场头 `1-1 日 内 地点`、`人物：`、`△`、`角色（提示）：台词`、
  `OS`/`VO`、`【闪回】/【闪出】`、`（字幕：）`、集头【人物/转折/卡点】）。
  → `data-model.md` 以真实样例为主格式，四行式兼容解析。
- **DR-35**：先写得清楚；格式混乱会在初审被淘汰。（01 §规范）

### 3.5 单集结构、期待、钩子

- **DR-14**：单集三段；前 30 秒三项、中段三项、末 30 秒四选一。（05 §单集结构）
- **DR-15/16**：大期待最晚第 2 集；全剧一个核心目标且具体；小期待按阶段拆。
  （06 §01–02）
- **DR-17**：四种信息差；阶段之间应有变化；信息差要建立在合理认知落差上
  （「九九乘法表降智」反例）。（06 §01–02）
- **DR-18**：钩子 = 把高潮拆两半；每集结尾；两类主干 + 子类 + 案例型。
  课程没有给「钩子类型表」的完整命名体系，只有台词/画面两类与其下手法；
  插件把课程提到的 11 种落成枚举，并允许自定义？——v0.1 不允许自定义，
  新增需改 spec。
- **DR-19**：无效钩子 = 内心独白复述目标/解释剧情；钩子必须自然停顿。（06 避坑）
- **DR-29**：节奏四要素：冲突连锁、台词字字千斤、关系变化、情绪控制。（05 §01–04）

### 3.6 情绪

- **DR-23**：四类情绪点；每集 1 小点、每 5–10 集 1 大点；允许蓄力集
  （《开局女帝做正宫》第 4 集不释放，第 5 集大点）。（07 §01–02）
- **DR-24**：男频三类痛点、女频两类痛点；痛点要具象成场景
  （泼酒、礼物转手送人）。（07 §01–03）
- **DR-25**：困境三尺度：简洁、留希望、有针对性；不要不劳而获、不要打脸路人。（07）
- **DR-36**：三误区：情绪自嗨、逻辑缺失、打脸路人。（07 避坑）

### 3.7 人物与成本

- **DR-27**：经济账：每加一场景可能多一天；夜戏/外景更贵；水下/高空/飙车/爆破/
  特效/大群演除非核心卖点否则简化。（08 §经济账）
- **DR-28**：角色数量与存在理由：核心 3–5、其余 ≤20、高潮集新角色 ≤2、
  日常集尽量 0；每个配角至少一个功能；写不出「他为什么必须存在」就重审。（08 §角色设计）
- **DR-37**：交稿前自查顺序：内核 → 落地 → 完整度。（08）

### 3.8 台词

- **DR-20/21**：口语化、简洁、合身份、推动剧情；三大功能；OS/VO 只作辅助。
  （01 §台词、09 §表现形式/三大功能）
- **DR-22**：少写心理多写行为；关键信息由正文传递，不能假设观众看过小传。
  （08 §镜头化/上帝视角、09）
- **DR-38**：每句自问「他会这么说吗」；分角色朗读；砍 1/3。这是可操作的修改法，
  也是评审 rubric 的检查项。
- **DR-39**：台词要能转化为动作/表情；避免「心碎了一地」这类不可拍句。
  （08 §镜头化、09 §四大问题）

### 3.9 合规

- **DR-26**：三红线：价值观与伦理（畸形婚恋观、违法得利未受罚、戏谑历史/民族）、
  政策与法律（时政宗教民族、法律硬伤、真实事件改编）、表现尺度（血腥暴力、
  性暗示、未成年不良引导）。「再好的创意，一旦踩红线，就直接出局。」（08 §合规）
- 合规是**提醒**不是判决：课程本身也要求制作方/平台评估，插件没有审核资质。

### 3.10 方法论

- **DR-30**：拉片三层次 + 四问；选择性拉片（结构简单→微创新→稀缺题材）。（01、05）
- **DR-31**：做减法；桥段窠臼要用「类型转换」破，不是换皮。（05）
- **DR-32**：选题三类、微创新三法、选题五问。（02）
- **DR-33**：起名抓卖点、保留原著核心词。（02）
- **DR-34**：网文转短剧：格式、观众视角、即时冲突、提纲先行。（10）

## 5. 技术决策（ADR）

### ADR-01 插件形态：Cordis 插件 + profile bundle，源码两包、发布一包

- **决定**：`packages/screenwriter` 是 host 插件（`name/inject/apply`，通过
  `ctx.tools.register(defineTool(...))` 注册工具）；`packages/bundle` 只带
  `dsh.bundle.patch` 与 `cordis.patch.yml`。发布时 `scripts/pack.mjs` 合并成一个 tarball。
- **依据**：`@deepseek-ai/dsh-tool-present` 的实际形状（`lib/index.js`：
  `name`、`inject`、`Config`、`apply`、`ctx.tools.register(defineTool(...))`）；
  profile 的 `dsh.profile.bundles` 与 `dsh.bundle.patch` 机制（`dsh` README）；
  同源项目的打包结论（`ai-novelist`：一个 tarball 只能一个包、patch 行必须是裸包名）。
- **风险**：合并包的构建脚本复杂；**复验**：P1 必须实际 `pnpm pack` + 装进 scratch
  profile（需用户批准）或至少解包检查 `package.json`/patch/入口。

### ADR-02 项目根按会话解析

- **决定**：`exec.agent.session.header.cwd` → 配置 `workspaceRoot` → 进程目录；
  每个根一个 `Store` 缓存。
- **依据**：DSH 的 workspace 是注册目录，session 携带 `cwd`；同源项目曾因
  `process.cwd()` 只认启动目录而出现「工作区无效」的 bug（`ai-novelist`
  `.plan/task_plan.md` Round 3）。
- **风险**：无 session 的测试执行需要显式传 root；**复验**：P3 用两个临时目录
  做隔离测试。

### ADR-03 Markdown 为内容权威，JSON 只存设置

- **决定**：故事/人物/大纲/剧本全部 Markdown；`project.json` 只存设置、确认、报告索引；
  文件手改即权威；语法错误报错不覆盖。
- **依据**：同源项目的存储改造（`docs/plan-markdown-storage.md`）证明「大 JSON 改一行
  要重写整份」不可持续；作者需要直接读/改稿。
- **代价**：多文件无事务；用「先内容后索引 + 逐项报告」缓解（`data-model.md` §8）。

### ADR-04 机检与评审分离

- **决定**：`scriptwriter_check` 纯确定性、零模型；`scriptwriter_review` 带 rubric、记录模型、
  不改文件；两者不合成分数。
- **依据**：课程里大量规则是「齐不齐」（可算）与「好不好」（只能判）的混合；
  混在一起会让作者误以为「机检通过 = 剧本合格」。这是本产品最重要的设计约束。

### ADR-05 作者确认门禁

- **决定**：settings → 第 1 集；opening → 第 4 集；delivery → 投稿包；
  final → 无 error 的机检。
- **依据**：课程 10 明确「提纲先行，审过再写分集」；同源项目出现过「模型从灵感
  直接写到第四章、设定从未给用户确认」的事故（`ai-novelist` Round 4）。
- **风险**：门禁过严会烦；解锁步骤必须清楚，且只卡「越级」，不卡草稿。

### ADR-06 运行上下文用同步快照

- **决定**：system prompt 的项目摘要来自内存快照，TTL 1.5s，后台刷新；渲染不读盘。
- **依据**：同源项目 prompt 实现（`host/prompt.ts`：prompt registry 同步解析，
  `SNAPSHOT_TTL_MS = 1500`）。
- **风险**：最多滞后 1.5s；可接受。

### ADR-07 打包陷阱

- **决定**：发布包名为 `@ai-scriptwriter/scriptwriter-bundle`（合并后），patch 行 `name` 用裸包名；
  `dsh plugin add` 必须带 `-w`；一个 tarball 只装一个包。
- **依据**：同源项目 README「Two constraints the packaging satisfies, both learned by testing」。
- **复验**：P7 的安装验收（SC-09）。

### ADR-08 v0.1 不做 Web 面板

- **决定**：只做 host 工具 + 文件。Web 面板列 v0.2 候选。
- **依据**：核心价值在方法论与可检查的稿子；面板是展示层，先证明工具链。
  同源项目的面板曾出现「打开空白/只在有会话时出现」等问题，成本不低。
- **待用户决定**：Q1。

### ADR-09 技法表放 `status craft`；另发独立 skill 包（v0.2 修订）

- **决定**：11 个技法主题仍由 `scriptwriter_status detail=craft` 按需返回；同时发布
  `dist/skill/ai-scriptwriter/`，`SKILL.md` + references 由同一份 `core/craft.ts` 生成。
- **依据**：DSH 技能发现依赖 `.dsh/skills` 或用户技能根（`dsh-skill-filesystem`），
  插件包不能保证把 skill 装进工作区；skill 包让「没有插件」的 agent 也能加载方法论。
  两份内容必须同源，否则会漂移。
- **代价**：构建多一个产物；用生成而不是手写来消除不一致。

### ADR-10 阈值分级：DR vs CFG

- **决定**：课程明确的规则用 `DR-*`；课程未明确的阈值用 `CFG-*`，项目可改。
- **依据**：课程未给台词字数、OS 占比、场次上限、成本档；把它们写成 DR 是造假。
- **实现**：`Finding.ruleRef` 接受两种前缀；报告里分开统计。

### ADR-11 锁定 DSH 0.2.1-rc.2

- **决定**：devDependencies 精确 `0.2.1-rc.2`；peer 用 `^0.2.1-rc.2`；
  升级前先改 plan 并重跑契约测试。
- **依据**：本机 `dsh --version = 0.2.1-rc.2`；同源项目曾因 `^` 解析到另一个 rc
  造成类型/运行时偏差（`.plan/task_plan.md` D4）。

### ADR-12 11 个工具，名字稳定

- **决定**：init / story / cast / outline / script / check / review / confirm /
  status / export / dissect。0.1.0 后只加 operation，不改名。
- **依据**：工具太多会稀释模型选择；太少会让一个工具塞进互斥语义。
  11 个与「立项→故事→人物→大纲→剧本→检查→评审→确认→状态→导出→拆解」一一对应。

### ADR-13 不联网、不造数据

- **决定**：无 HTTP 客户端、无爬虫、无平台 API；所有市场判断来自用户输入。
- **依据**：课程强调扫榜，但榜单是动态外部数据，插件没有可靠来源；
  伪造数据比没有数据更糟。

### ADR-14 写入失败要可解释

- **决定**：内容文件先写、索引后写；批量写返回 `written[]/failed[]`；
  解析失败不覆盖；可用 `@deepseek-ai/dsh-atomic-write`。
- **依据**：`dsh-atomic-write` 提供原子替换与锁；多文件无事务是 Markdown 方案的
  已知代价（同源 `plan-markdown-storage.md` §1）。

## 8. 结论

1. 课程足够支撑一个「结构化 + 可检查」的短剧编剧工具，但**不足以支撑一套精确评分**；
   产品必须区分「课程规则」与「插件默认」。
2. 最大的产品风险不是写不出剧本，而是**用确定性的口吻给出审美判断**；
   ADR-04 与 ADR-10 是防线。
3. 最大的工程风险是 DSH 版本漂移与打包细节；P1 先做「最小可安装插件」，
   在写业务逻辑前验证工具注册、prompt、模型路由、安装四条链路。
4. 课程口径不一致不是缺陷，是现实；产品用「可配置默认 + 明确标注」把它变成诚实。
